CSS em runtime, sem build e sem ficheiros.

O BreezeCSS interpreta utilitários como p[20px] e bg[primario] directamente no browser, gera apenas o CSS que usas e continua a observar o DOM para estilizar o que aparecer depois. Inspirado no Tailwind — mas com sintaxe própria, temas, plugins, componentes e vidro com refração real.

Introdução

O que é o BreezeCSS?

O BreezeCSS é um motor CSS em runtime: em vez de compilar utilitários numa etapa de build, ele lê os atributos class do teu HTML, interpreta cada utilitário e injecta uma única tag <style> com as regras necessárias. Um MutationObserver com debounce via requestAnimationFrame mantém tudo ao vivo — elementos criados por JavaScript, classes trocadas dinamicamente, tudo é processado automaticamente. É inspirado no Tailwind, mas totalmente em português, sem configuração obrigatória e com um sistema de plugins, componentes e temas embutido.

Runtime puro

Um <script> e pronto: o motor inicializa-se sozinho, lê a window.BreezeConfig e processa a página inteira.

Valores arbitrários infinitos

Qualquer propriedade mapeada aceita qualquer valor: w[calc(100%_-_20px)], bg[linear-gradient(...)], cols[3]…

Variantes compostas

hover, focus, first, odd, dark… e combináveis: md:hover:bg[primario] gera a media query + pseudo-class certas.

Temas nomeados

Cores, espaçamentos e fontes com nomes teus: bg[primario], p[sessao], font-family[titulo]. Variáveis CSS incluídas.

Componentes & plugins

addComponent('btn', [...]) cria componentes; plugins como o BreezeGlass, o BreezeProgress e o BreezeScrollbar acrescentam classes, mapeamentos e comportamentos novos.

Build & exportação

Para produção: exportar() descarrega o CSS vivo da página; build(html) compila HTML arbitrário sem tocar no DOM.

Como funciona, em três passos

  1. PASSO 1

    Escreves utilitários no atributo class — classes fixas (flex) ou arbitrárias (p[20px]).

  2. PASSO 2

    O parser separa variantes e breakpoints, resolve o valor (tema, underscores, processadores) e usa o cache para não repetir trabalho.

  3. PASSO 3

    As regras são injectadas numa <style> única (#breeze-v2-estilos) — cada regra entra uma só vez, mesmo que a classe apareça em mil elementos.

Sintaxe

prefixo[valor] — sem hífen

BreezeCSS
p[20px]

O prefixo liga directamente aos parênteses rectos: prefixo[valor]

Tailwind CSS (não é esta a sintaxe)
p-[20px]

O Tailwind usa um hífen antes do valor (prefixo-[valor]). No Breeze isso não funciona — nunca escrevas o hífen.

Anatomia de um utilitário composto

md:
breakpoint · ≥ 768px
hover:
variante · :hover
bg
prefixo · background-color
[linear-gradient(135deg,#00ff88,#22d3ee)]
valor arbitrário · _ vira espaço

Resultado: uma @media (min-width: 768px) que aplica o gradiente em .md\:hover\:bg\[…\]:hover. Qualquer combinação de breakpoint + variantes é válida.

As oito regras da sintaxe

01

O valor vai sempre entre [ ], colado ao prefixo: p[20px], bg[#0ea5e9]. Sem hífen, sem escala pré-definida.

02

_ vira espaço dentro do valor: w[calc(100%_-_20px)] → calc(100% - 20px). Funciona em calc(), clamp(), gradientes, rgb(), etc.

03

Excepções onde _ é literal: dentro de url(), var(), env(), attr() e src() o underscore não é convertido — caminhos e nomes de variáveis mantêm-se intactos.

04

! final = !important: bg[red!], w[100%!] — e em classes fixas flex!, hidden!; em componentes, btn! marca todas as propriedades internas.

05

Nomes do tema são resolvidos: se definiste tema.cores.primario, então bg[primario] gera a cor certa (o mesmo para espaçamentos e fontes).

06

border[...] é shorthand com ordem livre: border[dashed_2px_#00ff88] separa estilo, largura e cor — também por lado: border-t[2px_solid_red].

07

Transforms combinam-se: rotate[6deg] scale[1.05] translate-x[8px] no mesmo elemento produzem UMA declaração transform (por elemento + contexto de variantes).

08

Tudo é cacheado: cada classe é interpretada uma única vez; regras repetidas não voltam a entrar na folha de estilo. O processamento de mutações do DOM é agrupado por frame (rAF).

Da classe ao CSS gerado

p[20px]                      →  .p\[20px\] { padding: 20px; }

w[calc(100%_-_20px)]         →  .w\[calc\(100\%_-_20px\)\] { width: calc(100% - 20px); }

bg[primario]                 →  .bg\[primario\] { background-color: #00ff88; }   /* resolvido do tema */

hover:bg[#0ea5e9!]           →  .hover\:bg\[\#0ea5e9\!\]:hover { background-color: #0ea5e9 !important; }

flex!                        →  .flex\! { display: flex !important; }

border[solid_1px_#fff]       →  .border\[solid_1px_\#fff\] { border-style: solid; }
                                .border\[solid_1px_\#fff\] { border-width: 1px; }
                                .border\[solid_1px_\#fff\] { border-color: #fff; }

rotate[6deg] scale[1.1]      →  [data-breeze-id="b1"] { transform: rotate(6deg) scale(1.1); }  /* uma só declaração */

cols[3]                      →  .cols\[3\] { grid-template-columns: repeat(3, 1fr); }

md:hover:bg[primario]        →  @media (min-width: 768px) {
                                  .md\:hover\:bg\[primario\]:hover { background-color: #00ff88; }
                                }

Estado e media queries

Variantes & breakpoints

Prefixa qualquer utilitário com uma ou mais variantes (hover:bg[red]) e breakpoints (md:flex-row). Os breakpoints são mobile-first (min-width) e as variantes compõem-se à vontade: md:hover:focus:bg[primario].

BreezeGlass 1.0.0

O plugin glass cria superfícies de vidro em duas camadas: a camada 1 usa utilitários CSS ao vivo (backdrop-filter, tint, brilho especular e rebordo em box-shadow) e funciona em todos os browsers; a camada 2 acrescenta refração real com um mapa de deslocamento SVG (feDisplacementMap) gerado por canvas — só em Chromium, com degradação silenciosa nos restantes.

Opções do plugin

// Instância com opções personalizadas:
const VidroForte = BreezeGlass.criar({
  refracao: 'auto',   // 'auto' | true | false — camada 2 (só Chromium)
  intensidade: 16,    // refração por omissão (px)
  bisel: 0.3,         // largura do bisel da lente (0-1 da menor dimensão)
  resolucaoMax: 200   // resolução máxima do mapa de deslocamento
})
BreezeCSS.use(VidroForte)

// A instância global já vem pronta com os valores por omissão:
BreezeCSS.use(BreezeGlass)

BreezeDividers 1.2.0

O plugin dividers transforma qualquer elemento num divisor de secção. O formato é uma máscara SVG aplicada ao próprio elemento: a cor vem do bg (cor, gradiente ou imagem) e o tamanho das classes w / h normais. Sem elementos extra e sem SVG inline.

Activar o BreezeDividers

Bundle — depois do init

BreezeCSS.use(BreezeDividers)

Pela configuração

window.BreezeConfig = {
  plugins: [BreezeGlass, BreezeDividers]
}

Uso básico

<div class="w[100%] h[80px] bg[#000033] divider-wave"></div>

<!-- gradiente como cor do divisor -->
<div class="w[100%] h[100px] bg-gradient[90deg,#00ff88,#22d3ee] divider-diagonal"></div>

<!-- repetições entre [ ] e variantes do Breeze -->
<div class="w[100%] h[80px] bg[#101a2e] divider-wave[6] md:divider-zigzag-flip[17]"></div>

Plugin incluído no bundle

BreezeProgress 1.0.0

O plugin progress transforma qualquer elemento numa barra de progresso — sem JavaScript e sem acrescentar um único elemento ao HTML. No <body> mede o scroll da página inteira; num elemento com scroll interno mede o scroll dele; num elemento normal mede a passagem pelo ecrã (progresso de leitura). A barra é criada pelo plugin, vive fora do fluxo do elemento e só é visível enquanto ele estiver no ecrã — nunca estraga flex, grid nem nth-child. A barra no topo desta documentação é o próprio plugin em acção.

Activar o BreezeProgress

Bundle — depois do init

BreezeCSS.use(BreezeProgress)

Pela configuração

window.BreezeConfig = {
  plugins: [BreezeGlass, BreezeDividers, BreezeProgress]
}

Uso básico

<!-- barra de scroll da página inteira, fixa no topo do viewport -->
<body class="progress">

<!-- barra em baixo, com espessura, cor e trilho próprios -->
<body class="progress progress-bottom progress-h[6px] progress-color[#e11d48] progress-track[rgb(0_0_0/_.1)]">

<!-- progresso de scroll de um elemento com overflow interno -->
<div class="h[300px] overflow-auto progress progress-lg">…</div>

<!-- progresso de leitura de um artigo (passagem pelo ecrã) -->
<article class="progress progress-view progress-color[linear-gradient(90deg,#b18cff,#ff7ab8)]">…</article>

Três modos de medição (ao vivo)

body.progress · scroll da página
79% evento breeze:progress

A barra verde-água no topo do viewport enche enquanto percorres a documentação — é o <body> desta página a ser medido pelo plugin. A percentagem ao lado é actualizada pelo evento breeze:progress.

overflow-auto · progress-bottom · modo scroll

Faz scroll dentro desta caixa: o plugin detecta o overflow interno (modo auto) e mede scrollTop / (scrollHeight − clientHeight) deste elemento, não o da página.

A barra fica limitada à largura do elemento e só é visível enquanto ele estiver no ecrã — nunca ultrapassa as bordas.

O trilho recebe a cor de progress-track[…]; aqui usámos branco a 6% por baixo do gradiente verde-água.

Chegaste ao fim? O evento breeze:progress disparou a 100% neste elemento e a variável --progress ficou a 1.

Volta a subir: a animação usa progress-dur[80ms] por omissão — suave sem atrasar o scroll.

elemento normal · progress-view · leitura

Sem scroll interno, o plugin cai no modo view: mede a passagem deste cartão pelo ecrã.

A barra roxa enche à medida que o artigo atravessa o viewport, da entrada à saída da janela.

É o modo ideal para barras de leitura em artigos e posts — sem medir nada à mão nem criar elementos extra.

progress-right · barra vertical

Com progress-right (ou progress-left) a barra fica vertical, colada à borda do elemento, e enche de cima para baixo com scaleY. Combina com progress-reverse para inverter o sentido.

Classes do plugin

Classe Efeito
progress Activa a barra (obrigatória) — no body mede a página, noutros elementos aplica o modo
progress-top · bottom · left · right Posição (por omissão: top); left/right tornam a barra vertical
progress-sm · md · lg · xl Espessura 2 / 4 / 6 / 10 px
progress-rounded Arredondamento total (9999px) — ou progress-radius[…] arbitrário
progress-smooth · progress-instant Duração da animação: 200ms / 0ms (por omissão 80ms)

progress-auto · scroll · view Modo de medição — auto (padrão): scroll se houver overflow interno, senão passagem pelo ecrã

Valores arbitrários do plugin

Classe Controla

progress-color[#e11d48] Cor da barra — aceita gradientes: progress-color[linear-gradient(90deg,#f0f,#0ff)]
progress-track[rgb(0_0_0/_.1)] Cor do trilho (fundo) — transparente por omissão
progress-radius[9999px] Arredondamento da barra e do trilho
progress-z[50] z-index — 9990 por omissão, acima de cabeçalhos fixos
progress-dur[200ms] Duração da animação de enchimento

Extras para o programador

--progress
O elemento recebe a variável CSS --progress (0 a 1) — úsala para animar outras coisas em sincronia com a barra.
breeze:progress
Evento no elemento: e.detail = { progresso: 0..1, percentagem: 0..100 } — dispara sempre que a percentagem muda.
BreezeProgress.criar(…)
criar({ altura: 4, cor: '#3b82f6', z: 9990 }) cria uma instância com outros valores por omissão.

As variantes do Breeze funcionam nas classes do progress: md:progress-lg, dark:progress-color[#fff]… Com prefers-reduced-motion a animação passa a 0ms. Nota: se um antepassado do elemento tiver transform ou filter, a barra fixa pode não alinhar — nesse caso aplica progress-scroll / progress-view a um elemento fora desse antepassado.

Plugin incluído no bundle · novo

BreezeScrollbar 1.0.0

O plugin scrollbar personaliza a barra de scroll de qualquer elemento — ou da página inteira, com a classe no <html> ou no <body>. Controlas a espessura, a cor do polegar e do trilho, o raio, a folga e a cor ao passar o rato, tudo com classes prefixo[valor] e sem escrever ::-webkit-scrollbar à mão. A barra de scroll desta documentação é o próprio plugin em acção.

Activar o BreezeScrollbar

Bundle — depois do init

BreezeCSS.use(BreezeScrollbar)

Pela configuração

window.BreezeConfig = {
  plugins: [BreezeGlass, BreezeDividers, BreezeProgress, BreezeScrollbar]
}

Uso básico

<!-- barra de scroll da página inteira -->
<body class="scrollbar scrollbar-md scrollbar-thumb[#1c2942] scrollbar-thumb-hover[#2b3f66] scrollbar-gap[2px]">

<!-- caixa com scroll interno: barra fina, quadrada e laranja -->
<div class="h[300px] overflow-auto scrollbar scrollbar-thin scrollbar-square scrollbar-thumb[#ffb86b]">…</div>

<!-- polegar em gradiente, com folga e trilho -->
<div class="h[300px] overflow-auto scrollbar scrollbar-lg scrollbar-gap[3px] scrollbar-track[rgb(255_255_255_/_0.06)] scrollbar-thumb[linear-gradient(180deg,#b18cff,#ff7ab8)]">…</div>

<!-- esconde a barra mas continua a fazer scroll -->
<div class="h[300px] overflow-auto scrollbar-none">…</div>

Exemplos ao vivo

scrollbar-md · thumb verde · trilho suave

Faz scroll aqui dentro: o polegar é verde, o trilho é branco a 5% e as pontas são arredondadas por omissão (9999px).

Passa o rato sobre o polegar e ele passa a scrollbar-thumb-hover[#5dffb0].

As variáveis CSS ficam no próprio elemento (--scrollbar-thumb, --scrollbar-track…), por isso cada caixa pode ter a sua barra.

Sem JavaScript da tua parte: o plugin só marca o elemento e o CSS faz o resto.

scrollbar-lg · gradiente · scrollbar-gap[3px]

O polegar aceita gradientes no Chromium e no Safari.

A folga de 3px afasta o polegar das bordas do trilho — o trilho continua visível à volta dele.

No Firefox o gradiente não se aplica (só cores simples) e a barra usa a cor por omissão.

Útil para listas, painéis laterais e blocos de código com o tema da tua marca.

dois eixos · scrollbar-square · scrollbar-corner

Este conteúdo é mais largo e mais alto que a caixa, por isso aparecem as duas barras.

Onde as duas se cruzam fica o canto, colorido por scrollbar-corner[#2a1f10].

Com scrollbar-square o polegar e o trilho ficam sem arredondamento.

Mais uma linha para garantir scroll vertical.

E outra, para fechar.

scrollbar-none · sem barra, com scroll

Aqui não há barra visível, mas a roda do rato, o toque e o teclado continuam a fazer scroll.

É o padrão para carrosséis, abas e listas horizontais onde a barra só atrapalha.

Esconder a barra tira uma pista visual — usa-o quando o resto do desenho já mostra que há mais conteúdo.

scrollbar-none funciona sozinho, não precisa da classe scrollbar.

scrollbar-thin · md · lg · xl Espessura 6 / 10 / 14 / 18 px (por omissão 8px)

scrollbar-none Esconde a barra; o elemento continua a fazer scroll

Extras para o programador

data-breeze-scrollbar
O plugin marca os elementos activos com este atributo (valor none quando a barra está escondida). É nele que assenta o CSS que injecta no <head>.
Página inteira
A barra da página é do <html>. Se a classe estiver no <body>, o plugin copia as variáveis e o atributo para o <html> por ti.
BreezeScrollbar.criar(…)
criar({ tamanho: 8, thumb: '…', thumbHover: '…' }) cria uma instância com outros valores por omissão.

As variantes do Breeze funcionam nas classes do scrollbar: md:scrollbar-lg, dark:scrollbar-thumb[#fff], hover:scrollbar-thumb[red]… Suporte por browser: o Chromium e o Safari usam ::-webkit-scrollbar e respeitam tudo o que está acima. O Firefox só tem scrollbar-color e scrollbar-width: cores (simples), scrollbar-none e a escolha entre fina (por omissão) e normal (scrollbar-lg / scrollbar-xl) funcionam; raio, folga, canto e cor de hover não existem lá.

Abstracção leve

Componentes

Um componente é um nome que expande para uma lista de classes — o parser trata-o como qualquer outro utilitário, incluindo variantes e breakpoints. E com o sufixo ! todas as propriedades internas ficam com !important. 

BreezeCSS.addComponent('btn', [
  'bg-gradient[135deg,#00ff88,#22d3ee]',
  'text[#04121f]', 'fw[700]',
  'px[20px]', 'py[10px]', 'rounded-xl',
  'cursor-pointer', 'transition', 'duration[200ms]',
  'hover:scale[1.05]', 'hover:shadow-lg'
])

// Depois, no HTML:
// <button class="btn">Guardar</button>
// <button class="btn!">Guardar (com !important em tudo)</button>

Ao vivo — registados por esta própria página:

<button class="btn-breeze"> e <button class="btn-glass">

API

API JavaScript

O objecto global window.BreezeCSS expõe tudo o que o motor faz — os exemplos abaixo executam-se de verdade nesta página.

Método Descrição
init(config?) Inicializa o motor com o objecto de configuração (as mesmas chaves do window.BreezeConfig). Sem chamada explícita acontece sozinho no carregamento, lendo window.BreezeConfig. Só funciona uma vez: se o motor já arrancou, usa reiniciar() antes — ver a secção Configuração.
use(plugin) Regista um plugin depois do init — é assim que se activam os plugins do bundle (BreezeGlass, BreezeDividers, BreezeProgress, BreezeScrollbar). Antes do init, passa-os na chave plugins da configuração.
processar() Reprocessa todos os elementos do DOM (útil depois de registar classes ou componentes novos).
reiniciar() Para o observador, limpa estilos e cache e permite um novo init() do zero — é o que permite aplicar uma configuração nova depois do arranque automático.
build(html, opcoes?) Compila um string de HTML para CSS sem tocar no DOM (modo offline). Opções: { minificar }.
exportar(opcoes?) Descarrega o CSS real da página como ficheiro .css. Opções: { nome, minificar, incluirCabecalho }.
addComponent(nome, classes) Regista um componente (lista de classes) — ver a secção anterior.
addFixedClass(nome, estilo) Acrescenta uma classe fixa: 'caixa' → 'padding: 24px; border-radius: 12px'.
addMapping(prefixo, prop) Mapeia um prefixo arbitrário novo (ex.: 'sombra' → 'box-shadow').
addVariant(nome, pseudo) Nova variante (ex.: 'foco-dentro' → ':focus-within').
addBreakpoint(nome, tam) Novo breakpoint (ex.: '3xl' → '1920px').
addProcessor(prefixo, fn) Pós-processador do valor de um prefixo (é assim que cols[3] vira repeat(3, 1fr)).
stats() Estatísticas de cache e configuração — experimenta no botão abaixo.
versao Propriedade com a versão actual ("2.2.5").

Configuração

window.BreezeConfig

Toda a configuração é opcional. Define window.BreezeConfig antes do <script> do motor — ou passa o mesmo objecto a BreezeCSS.init(cfg) (ver mais abaixo quando isso funciona).

Chave Tipo Omissão Descrição
log boolean true Logs do motor na consola (com o banner verde). false = silencioso.
debug boolean false Logs DEBUG — cada regra à medida que entra na folha de estilo.
reset boolean true Mini-reset: * { margin: 0; padding: 0 } + box-sizing: border-box.
scrollSmooth boolean true Injecta html { scroll-behavior: smooth } automaticamente.
prefix string '' Prefixa todas as classes para evitar conflitos: 'bz-' → bz-flex, bz-bg[red].
safelist string[] [] Classes pré-geradas no arranque, mesmo antes de aparecerem no DOM.
plugins Plugin[] [] Plugins registados no init, por exemplo [BreezeGlass, BreezeScrollbar] (padrão para ficheiros separados).
tema object {} { cores, espacamento, fontes } — valores nomeados resolvidos nas classes.
breakpoints object sm…2xl Adiciona ou substitui breakpoints (min-width).
variantes object hover…dark Adiciona ou substitui variantes (pseudo-classes e estados).
classesFixas object … Acrescenta ou sobre escreve classes fixas.
mapaPropriedades object … Acrescenta ou sobre escreve prefixos arbitrários.

Temas: valores com nome

window.BreezeConfig = {
  tema: {
    cores: { primario: '#00ff88', aviso: '#ffb86b', erro: '#ff5f6b' },
    espacamento: { sessao: '96px', cartao: '24px' },

// <div class="bg[primario] p[cartao]">

Bónus: o Breeze também injecta variáveis CSS em :root — --breeze-primario, --breeze-spacing-cartao, --breeze-font-titulo — para usares fora das classes.

Prefixo e safelist

window.BreezeConfig = {
  prefix: 'bz-',                       // bz-flex, bz-p[20px], bz-hover:bg[red]
  safelist: ['hidden', 'md:flex-row']  // geradas logo no arranque
}

Alternativa: BreezeCSS.init(cfg)

window.BreezeConfig e BreezeCSS.init(cfg) aceitam exactamente as mesmas chaves (tema, prefix, plugins, safelist, breakpoints…): o arranque automático limita-se a chamar BreezeCSS.init(window.BreezeConfig || {}). Tudo o que está na tabela acima pode, portanto, ser passado directamente ao init(). O que muda é quando a chamada tem efeito. 

<!-- bundle no <head>, sem defer/async: o init() manual corre antes do automático -->
<script src="breeze.bundle.js"></script>
<script>
  BreezeCSS.init({
    prefix: 'bz-',
    tema: { cores: { primario: '#00ff88' } },
    plugins: [BreezeGlass, BreezeDividers, BreezeProgress, BreezeScrollbar]
  })
</script>
Funciona logo a seguir ao bundle
Quando o bundle é carregado de forma síncrona e a página ainda está a ser lida, o teu init(cfg) corre primeiro. O arranque automático (no DOMContentLoaded) já encontra o motor iniciado e é ignorado — vês apenas o aviso "já foi inicializado" na consola, e só com log activo.
Depois do arranque automático
Com defer, async, bundle no fim do <body> ou carregado por JavaScript, o motor já arrancou e um init(cfg) é ignorado. Chama antes BreezeCSS.reiniciar(): limpa estilos e cache e deixa o novo init(cfg) fazer tudo de novo. 
// motor já iniciado (defer, fim do body…): reinicia e aplica a nova configuração
BreezeCSS.reiniciar()
BreezeCSS.init({ prefix: 'bz-', plugins: [BreezeGlass, BreezeScrollbar] })

Atenção: BreezeCSS.init() sem argumentos não lê o window.BreezeConfig — só o arranque automático o faz. O init() também só funciona uma vez (daí o reiniciar()). Para plugins, usa a chave plugins da configuração ou use() depois do init.

Boas práticas

Práticas recomendadas

O BreezeCSS é flexível por natureza — mas projetos que crescem precisam de consistência. Estas práticas vêm do uso real do motor em produção: como definir um tema, nomear componentes, organizar valores arbitrários e preparar o CSS para entrega. Nenhuma é obrigatória — mas todas poupam retrabalho quando o projeto passa de dez para cem ecrãs.

Tema antes de classes

Define cores, espaçamentos e fontes no tema — depois usa bg[primario] em vez de bg[#00ff88].

Componentes para o repetido

Se repetes a mesma lista de classes três vezes, cria um componente: btn, card, chip.

Fixa primeiro, arbitrária depois

Usa flex, rounded-xl quando existem. Só cai para rounded[13px] se precisares mesmo.

!important com conta-gotas

Reserva ! para integrações com CSS externo. Dentro do Breeze, ordena as classes e deixa a especificidade trabalhar.

1. Define o tema uma vez, usa em todo o lado

Este é o passo com mais impacto. Em vez de espalhar bg[#0ea5e9] por 30 sítios, defines primario uma vez e mudas a cor num só lugar. 

window.BreezeConfig = {
  tema: {
    cores: {
      primario: '#00ff88',
      secundario: '#22d3ee',
      aviso: '#ffb86b',
      erro: '#ff5f6b',
      fundo: '#0a0e16',
      superficie: '#0f1e33',
      texto: '#c9d6e8',
      textoFraco: '#8fa3bf'
    },
    espacamento: {
      xs: '4px', sm: '8px', md: '16px', lg: '24px',
      cartao: '24px', sessao: '72px'
    },
    fontes: {
      titulo: "'Sora', system-ui, sans-serif",
      corpo: "'Inter', system-ui, sans-serif",
      mono: "'JetBrains Mono', monospace"
    }
  }
}

Porquê: mudar de tema escuro para claro passa a ser uma alteração no BreezeConfig — não uma caça ao #00ff88 em 200 ficheiros. Bónus: cada valor do tema é exposto como variável CSS (--breeze-primario), por isso podes usá-lo em CSS puro, SVG inline ou bibliotecas externas.

2. Fixas por omissão, arbitrárias por exceção

Bom 
<div class="flex items-center gap[sm] p[md] rounded-xl bg[primario]">
  <span class="text-size[14px] fw[600] text[#04121f]">Pronto</span>
</div>

flex, rounded-xl e bg[primario] são valores do sistema. Se amanhã quiseres outro raio, mudas no tema.

Evita 
<div class="flex items-center gap[7px] p[17px] rounded[11px] bg[#00ff88]">
  <span class="text-size[13.8px] fw[600] text[#04121f]">Pronto</span>
</div>

Valores "quase iguais" a cada canto, densidade visual inconsistente. Custa pouco e parece pouco — mas não escala.

3. Sobe o repetido para componente

Se a mesma sequência de classes aparece mais de duas vezes, é sinal de componente. Fica mais fácil de ler, de mudar e de manter coerência. 

BreezeCSS.addComponent('btn', [
  'bg-gradient[135deg,#00ff88,#22d3ee]', 'text[#04121f]', 'fw[700]',
  'px[20px]', 'py[10px]', 'rounded-xl', 'cursor-pointer', 'transition',
  'hover:scale[1.05]', 'duration[200ms]'
])

BreezeCSS.addComponent('chip', [
  'glass', 'glass-sm', 'rounded-full',

// Depois, no HTML:
// <button class="btn">Guardar</button>
// <span class="chip">Novo</span>
// <button class="md:btn btn!">Guardar (importante)</button>

4. Nomenclatura consistente

PREFIXO

Em projetos grandes, ativa o prefix para não colidir com CSS de terceiros: BreezeConfig = { prefix: 'bz-' }. Depois é bz-flex, bz-bg[red].

IDIOMA

O Breeze é 100% em português — usa tema.cores.primario e não theme.colors.primary. Misturar idiomas só confunde quem chega depois.

ORDEM DE CLASSES

Não importa para o resultado — o motor resolve pela especificidade das regras. Mas mantém uma ordem (layout → cor → tipografia → efeitos) para leitura previsível.

COMPONENTES

Nomes no singular, curtos, sem prefixo: btn, card, chip, nav. Variantes via sufixo: btn-secundario, card-destaque.

5. Mobile-first, sempre

Os breakpoints do Breeze são todos min-width. Escreve primeiro o layout para o telemóvel e depois adiciona md: e lg: para crescer. Evita max-md: — não existe.

Bom (mobile-first)
<div class="grid cols[1] md:cols[2] lg:cols[3] gap[16px]">…</div>

Uma coluna no telemóvel, duas no tablet, três no desktop. Um único atributo class, três layouts.

Evita (desktop-first)
<div class="grid cols[3] max-md:cols[2] max-sm:cols[1] gap[16px]">…</div>

Ordem decrescente é mais difícil de manter e o Breeze não tem variantes max-* — estarias a lutar contra o motor.

6. Acessibilidade não é opcional

Contraste

Verifica sempre o par cor-de-texto / fundo. text[#8fa3bf] sobre bg[#0a0e16] passa AA; text[#444] não.

Foco visível

Se usares outline-none, substitui por um anel visível: focus:ring[2px] ou focus:border-color[#00ff88].

Movimento reduzido

O BreezeGlass já respeita prefers-reduced-motion. Para as tuas animações, envolve em @media (prefers-reduced-motion: no-preference).

Texto escondido

Para ícones com significado, usa sr-only com um <span> descritivo. Para decorativos, aria-hidden="true".

7. Do runtime à produção

Safelist para classes dinâmicas

Classes geradas por JavaScript (ex.: bg[ + cor + ]) nunca aparecem no HTML inicial. Declara-as em safelist.

Exportar antes do deploy

Em produção, corre BreezeCSS.exportar() e serve o .css estático. O browser deixa de precisar do motor — menos JavaScript, primeiro paint mais rápido.

Evita valores em loop

Se gerares classes em forEach com valores únicos (ex.: w[317px]), o CSS cresce sem limite. Prefere valores do tema ou um conjunto fixo de tamanhos.

Monitoriza o cache

O motor guarda em cache cada classe interpretada. Se gerares classes dinamicamente em massa, chama BreezeCSS.stats() para ver se o cache está a crescer demais.

8. Anti-padrões a evitar

Hífen no valor

p-[20px] não funciona — é sintaxe Tailwind. O Breeze usa p[20px], colado.

Estilos inline

style="padding:20px" foge ao motor e não aparece no CSS exportado. Usa uma classe arbitrária: p[20px].

Tudo !important

Se precisas de ! em tudo, o problema é estrutura de CSS e não de força bruta. Reserva para pontes com bibliotecas externas.

Misturar idiomas

tema.cores.primario + tema.colors.primary = confusão. Escolhe um idioma e fica com ele.

9. Checklist antes do deploy

  • Tema definido — cores, espaçamentos e fontes no BreezeConfig.
  • Componentes criados — padrões repetidos (>2×) transformados em componentes.
  • Safelist verificada — classes geradas por JS estão declaradas.
  • Contraste AA — pares texto/fundo testados.
  • Foco visível — todos os elementos interativos têm indicador.
  • Mobile-first — layouts testados em 3 larguras (telemóvel, tablet, desktop).
  • CSS exportado — exportar() corrido e .css incluído no build de produção.
  • Plugins ativos — glass, dividers, progress e scrollbar registados com use().

Regra de ouro: se uma classe arbitrária aparece três vezes, cria um valor no tema. Se a mesma sequência aparece três vezes, cria um componente. Se precisas de ! em três sítios, repensa a estrutura. Consistência ganha sempre à flexibilidade — e o Breeze dá-te as duas, se souberes quando escolher.

Produção

Build & exportação

O runtime é óptimo para desenvolver — mas se quiseres entregar CSS estático, o motor também sabe: exportar() lê as regras reais da folha de estilo viva e build(html) compila HTML arbitrário sem tocar no DOM. 

// 1. Exportar o CSS desta página — descarrega um ficheiro .css:
BreezeCSS.exportar({ nome: 'breeze-docs', minificar: false })

//    • lê o <style> real injectado no browser (não um cache interno)
//    • converte seletores [data-breeze-id="bN"] de volta para classes
//    • o resultado é independente do Breeze — pronto para produção

// 2. Compilar HTML arbitrário para CSS (requer DOMParser):
const html = '<div class="flex gap[12px] p[24px]">…</div>]'
const css = BreezeCSS.build(html, { minificar: true })

Fluxo recomendado: desenvolve com o runtime aceso; no fim, chama exportar() (ou usa build() num script de publicação) e passa a servir o .css gerado — sem JavaScript de estilos em produção.
