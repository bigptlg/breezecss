01 / 16Começar

O BreezeCSS, pronto para produção

O BreezeCLI 1.0.0 transforma classes do BreezeCSS presentes no teu projeto em CSS estático, podendo também gerar um runtime JavaScript com os plugins necessários. O motor CSS deixa de ter de analisar e gerar estilos no navegador.

O CLI utiliza o motor real breeze.bundle.js numa VM Node.js, para manter a geração de CSS alinhada com o BreezeCSS v2.2.5. Não necessita de dependências npm externas; requer Node.js 18 ou superior.

BreezeCSS em runtime BreezeCLI em modo compilado
O navegador interpreta classes e gera CSS O CSS é gerado antes da publicação
O bundle contém motor + plugins O runtime pode conter apenas os plugins necessários
Classes adicionadas em runtime podem ser compiladas no browser Classes dinâmicas devem ser detetáveis no build ou entrar na safelist
Configuração aplicada durante a execução Tema e componentes são extraídos durante a compilação

Quando usar? Usa o BreezeCSS original para protótipos e páginas sem build. Usa o BreezeCLI para publicar CSS estático, separar ficheiros por página e reduzir o trabalho feito no navegador.

02 / 16Começar

Da página HTML ao CSS e JS compilados

Não precisas de descarregar o código fonte nem copiar uma pasta breeze/. Abre o terminal na raiz do teu projeto, onde estão os ficheiros HTML, e executa o pacote oficial publicado no npm. O comando deteta tema, classes, componentes e plugins, gera os ficheiros e atualiza o HTML automaticamente.

BASH
npx breezecss-cli --split --plugins auto --inject

A estrutura esperada é semelhante a esta:

TEXT
meu-site/
├── index.html
├── contacto.html
├── css/                   # gerado pelo CLI
│   ├── index.css
│   └── contacto.css
└── js/                    # gerado quando necessário
    ├── index.runtime.js
    └── contacto.runtime.js

Os ficheiros css/ e js/ são saídas do comando, não precisam de existir antes. Se já tens um <script> a carregar o bundle original, --inject procura substituí-lo pelo runtime compilado.

HTML
<!-- Referências geradas automaticamente para index.html -->
<link rel="stylesheet" href="css/index.css" data-breeze-cli="css">
<!-- breeze:css -->
<script src="js/index.runtime.js" data-breeze-cli="runtime"></script>
<!-- breeze:runtime -->

Importante: o CLI gera o runtime quando há plugins que precisam de JavaScript, ou quando pedes --runtime. Se só precisares de CSS, usa --no-runtime.

03 / 16Começar

Executar via npx, instalar ou automatizar

Pacote oficial: breezecss-cli no npm. Requisitos: Node.js ≥ 18 e npm/npx. O CLI não exige dependências npm externas. O executável instalado chama-se breeze.

1. Sem instalação prévia — npx (recomendado)

Entra na pasta do teu site e executa diretamente o pacote público. Na primeira execução, o npm pode perguntar se autorizas o descarregamento.

CMD / TERMINAL
npx breezecss-cli --version
npx breezecss-cli --split --plugins auto --inject

2. Instalação local no projeto

Instala como dependência de desenvolvimento. Depois, usa npx breeze (o nome do executável é diferente do nome do pacote):

CMD / TERMINAL
npm install -D breezecss-cli
npx breeze --version
npx breeze --split --plugins auto --inject

3. Script npm para projetos recorrentes

Depois de instalar o pacote localmente, adiciona o comando ao package.json. O npm encontra automaticamente node_modules/.bin/breeze quando executa um script:

JSON
{
  "scripts": {
    "compilar": "breeze --split --plugins auto --inject",
    "compilar:prod": "breeze --split --plugins auto --inject --minify"
  }
}
CMD / TERMINAL
npm run compilar
npm run compilar:prod

Windows: após instalação local, escrever breeze diretamente no CMD pode devolver «não é reconhecido». Usa npx breeze ou npm run compilar. Sem instalação local, usa npx breezecss-cli; não uses npx breeze isoladamente, pois breeze é também o nome de outro pacote no npm.

O CLI analisa a pasta atual. Mantém os HTML nessa pasta ou indica-os com --file. Se tiveres uma cópia do código fonte dentro do projeto, o CLI exclui os próprios exemplos e testes da descoberta.

04 / 16Compilação

Um ficheiro, vários ficheiros ou páginas específicas

Comando Resultado
npx breezecss-cli Um único css/breeze.css com as classes do projeto
npx breezecss-cli --split Um CSS por página, como css/index.css
npx breezecss-cli --file index.html Compila apenas a página indicada
npx breezecss-cli --file a.html --file b.html --split Compila só as páginas selecionadas
npx breezecss-cli --split --plugins auto --inject CSS + runtime dos plugins + referências no HTML
npx breezecss-cli --watch --inject Reconstrói ao guardar e reinjeta as referências

Saídas personalizadas

BASH
npx breezecss-cli --split --plugins auto --inject --out dist/css --js-out dist/js --minify

Podes usar --name po para mudar o nome do CSS único, ou --clean para limpar a pasta CSS de saída antes de compilar. Atenção: --clean remove o conteúdo da pasta de saída selecionada; não a uses numa pasta com ficheiros que queiras conservar.

06 / 16Configuração

O tema do HTML é detetado sem --init

Na versão 1.0.0, o CLI procura BreezeCSS.init({ ... }) e window.BreezeConfig nos scripts do projeto. Não precisas de acrescentar --init index.html ao comando habitual.

HTML
<script>
  BreezeCSS.init({
    plugins: [BreezeGlass, BreezeProgress, BreezeScrollbar],
    tema: {
      cores: {
        primaria: '#003',
        secundaria: '#005',
        tercearia: '#fff'
      }
    }
  });
</script>

O CSS gerado passa a resolver classes como bg[secundaria], text[tercearia] e progress-track[tercearia] para valores de cor reais:

CSS
:root {
  --breeze-primaria: #003;
  --breeze-secundaria: #005;
  --breeze-tercearia: #fff;
}
.bg\[secundaria\] { background-color: #005; }
.text\[tercearia\] { color: #fff; }
.progress-track\[tercearia\] { --progress-track: #fff; }

Ordem de prioridade

Valores predefinidos → init descoberto → breeze.config.js → opções CLI. Se utilizares --file, a descoberta dá prioridade à página indicada. Sem --file, os HTML da raiz são preferidos aos ficheiros aninhados.

BASH
# Substituição pontual de uma cor no terminal
npx breezecss-cli --tema cores.primaria=#003

# Configuração JSON completa
npx breezecss-cli --tema '{"cores":{"primaria":"#003"}}'

Limitação atual: o tema é global por compilação. Para páginas com temas distintos, faz builds separados ou utiliza uma configuração comum. Valores nomeados do tema em shorthands multipartes como border[solid_2px_secundaria] não são resolvidos pelo motor; usa border-color[secundaria] em separado.

07 / 16Configuração

Configuração centralizada (opcional)

Podes guardar opções no ficheiro breeze.config.js, na raiz do projeto. É útil quando o site cresce ou quando queres manter um tema único.

JS
// breeze.config.js
module.exports = {
  split: true,
  inject: true,
  plugins: 'auto',
  minify: true,
  out: 'dist/css',
  jsOut: 'dist/js',
  tema: {
    cores: {
      primaria: '#003',
      secundaria: '#005',
      tercearia: '#fff'
    }
  },
  componentes: {
    btn: ['p[15px]', 'rounded[10px]', 'hover:translate-y[-3px]']
  }
};

Depois podes compilar apenas com:

BASH
npx breezecss-cli

Não é obrigatório criar este ficheiro: a descoberta automática de BreezeCSS.init() continua disponível. Para forçar um ficheiro de configuração específico, usa --config caminho/ficheiro.js.

08 / 16Configuração

addComponent() também funciona no build

O CLI descobre as chamadas a BreezeCSS.addComponent() nos scripts do projeto, expande os membros e gera as regras CSS para o nome do componente. Isso inclui variantes, breakpoints e dependências de plugins.

HTML
<script>
  BreezeCSS.addComponent('btn', [
    'no-underline', 'text[tercearia]', 'p[15px]',
    'rounded[10px]', 'hover:translate-y[-3px]'
  ]);
  BreezeCSS.addComponent('card', [
    'glass', 'glass-dark', 'rounded[20px]', 'p[32px]', 'md:p[64px]'
  ]);
</script>

<a class="btn" href="#contacto">Contactar</a>
<article class="card">Conteúdo</article>

A expansão é recursiva, aceita componentes que referenciam outros componentes e protege contra ciclos. Com --split, cada página recebe os componentes efetivamente usados nela. Também podes declarar componentes em breeze.config.js.

Importante: os nomes de componentes devem ser definidos nos ficheiros que o CLI analisa. Evita manter exemplos ou versões alternativas dos mesmos componentes dentro da pasta do teu site; o pacote BreezeCLI exclui automaticamente apenas os seus próprios exemplos e testes.

09 / 16Runtime

O que é compilado e o que continua dinâmico?

O CLI consegue gerar CSS estático para todos os seis plugins, mas alguns efeitos dependem de JavaScript no navegador. O --plugins auto analisa classes, componentes, templates e configuração para escolher os necessários.

Plugin CSS compilado Runtime JS
BreezeGlass Glass, blur, tons, acessibilidade Necessário para glass-refract
BreezeDividers Máscaras e divisores SVG Não necessita de JS
BreezeProgress Variáveis, dimensões e cores Cria e atualiza a barra no scroll
BreezeScrollbar Scrollbar em WebKit/Firefox Aplica atributos e espelhamento body → html
BreezeBackgrounds Presets e variáveis Gera SVG/SMIL e observa visibilidade
BreezePreloader Animações e estilos Controla overlay, load e saída
HTML
<body class="progress progress-color[linear-gradient(90deg,#005,#003)]
             progress-track[tercearia]
             scrollbar scrollbar-track[#003] scrollbar-thumb[#ffffff88]">
  <div class="custom-bg[topo] custom-bg-animate"></div>
</body>

Para uma página com apenas Glass e Dividers sem efeitos dinâmicos, podes usar --no-runtime. Para efeitos como Progress, Backgrounds e Preloader, mantém o runtime gerado pelo CLI. Não precisas de carregar a CDN original ao mesmo tempo.

10 / 16Runtime

Um runtime autónomo por página

O Runtime Builder extrai o código necessário dos plugins do bundle original e cria js/<pagina>.runtime.js. O núcleo mantém uma API de compatibilidade para projetos existentes:

JS
BreezeCSS.init({ /* plugins e tema */ });
BreezeCSS.use(/* plugin */);
BreezeCSS.addComponent('card', ['glass', 'p[20px]']);
BreezeCSS.processar();
BreezeCSS.reiniciar();

// Para limpeza explícita do runtime compilado:
window.__breezeRuntime?.destruir();

No modo compilado, build() e exportar() não voltam a gerar CSS no navegador: a geração já ocorreu no terminal. Tema e prefixo devem ser definidos antes do build; alterá-los apenas no browser não recompila as regras estáticas.

O runtime também tem proteção contra inicialização duplicada. Os plugins mantêm os seus observadores e mecanismos de atualização dinâmica; o CSS de classes totalmente novas continua a depender de um novo build ou de --safelist.

11 / 16Runtime

--inject substitui o bundle sem interromper outros scripts

Quando encontra referências reconhecidas ao breeze.bundle.js, breeze.min.js ou scripts individuais do Breeze, o CLI substitui a primeira pelo runtime compilado e trata referências repetidas. Também injeta ou atualiza a folha CSS.

BASH
npx breezecss-cli --split --plugins auto --inject

O que acontece ao JavaScript inline?

As chamadas independentes a métodos de BreezeCSS são protegidas para evitar ReferenceError caso o runtime não esteja disponível. O restante código do mesmo <script> permanece fora da condição.

JS
// Exemplo de saída protegida
if (typeof BreezeCSS !== 'undefined') {
  BreezeCSS.init({ tema: { cores: { primaria: '#003' } } });
}

if (typeof BreezeCSS !== 'undefined') {
  BreezeCSS.addComponent('card', ['glass', 'p[32px]']);
}

// Continua a executar sem depender de BreezeCSS:
Emerge.init();
window.addEventListener('load', () => Emerge.refresh());

Os guards são identificados por comentários internos e não se acumulam em execuções repetidas. O código de configuração continua disponível no HTML para futuras compilações. A proteção automática não altera scripts JS externos nem chamadas embutidas em expressões complexas.

Injeção segura e repetível

O CLI usa marcadores <!-- breeze:css --> e <!-- breeze:runtime -->, ajusta caminhos relativos em subpastas e evita duplicar referências quando o comando é executado várias vezes. O posicionamento do runtime respeita scripts inline que dependem de BreezeCSS.

12 / 16Integração

Classes declaradas em templates também contam

Com --tpl, o CLI procura classes em JSX, TSX, Vue, Angular e Svelte, para que as classes detetáveis estaticamente também entrem no CSS. --plugins auto já analisa templates para identificar dependências dos plugins; --tpl força a inclusão de classes em qualquer modo.

BASH
npx breezecss-cli --split --plugins auto --tpl --inject
JSX
// JSX: classes literais podem ser encontradas durante a análise
export default function Card() {
  return <article className="glass rounded[20px] p[32px]">
    Conteúdo
  </article>;
}

Os plugins com MutationObserver mantêm a capacidade de reagir a elementos adicionados ou removidos por frameworks. Contudo, classes construídas dinamicamente — por exemplo, uma string montada a partir de variáveis — podem não ser detetadas pelo analisador estático.

BASH
npx breezecss-cli --safelist 'bg[#003]' --safelist 'text[#fff]'

Para aplicações SPA: o CLI compila classes encontradas no código do projeto; não executa a tua aplicação React/Vue. Quando a renderização só produz classes em runtime, adiciona-as à safelist ou garante que aparecem de forma estática nos templates.

13 / 16Integração

Guarda o HTML. O CLI recompila.

O modo --watch observa ficheiros HTML, configuração e motor e volta a compilar quando deteta alterações. Com --inject, as referências geradas também são atualizadas.

BASH
npx breezecss-cli --watch --split --plugins auto --inject

Um fluxo simples de desenvolvimento:

  1. Escreve classes BreezeCSS no HTML e define o tema em BreezeCSS.init() ou no breeze.config.js.
  2. Mantém o terminal com --watch ativo enquanto editas.
  3. Confirma os ficheiros em css/ e js/ e os links inseridos no HTML.
  4. Antes de publicar, executa um build final com --minify e verifica a página num navegador.
BASH
npx breezecss-cli --split --plugins auto --inject --minify --verbose

Se quiseres diagnosticar classes ignoradas ou problemas de deteção, acrescenta --verbose.

14 / 16Integração

Como o CLI funciona por dentro

A estrutura abaixo descreve os ficheiros internos do pacote npm, não uma pasta que devas criar no teu site.

O CLI usa o breeze.bundle.js real numa VM Node.js com um DOM mínimo. Analisa o HTML, descobre as classes e componentes, gera o CSS, adapta seletores dinâmicos para CSS estático e monta os ficheiros de saída.

TEXT
breeze/
├── bin/breeze.js         # entrada CLI
├── lib/
│   ├── initscan.js       # descoberta do tema e init
│   ├── components.js     # addComponent e expansão
│   ├── plugdep.js        # dependências de plugins
│   ├── runtime.js        # geração do runtime JS
│   ├── js-guard.js       # proteção de chamadas inline
│   ├── htmlscan.js       # leitura e injeção no HTML
│   ├── cssgen.js         # montagem de CSS
│   └── engine.js         # VM com o motor original
├── vendor/breeze.bundle.js
├── test/
└── exemplo/

O motor é procurado nesta ordem: --engine, bundle presente no projeto (ou pastas superiores), e por último a cópia incluída no pacote npm em vendor/. Não precisas de copiar o bundle para o projeto. Os testes da ferramenta estão incluídos no repositório do código fonte e no pacote publicado.

15 / 16Ajuda

Diagnóstico rápido

npx breezecss-cli não encontra o executável

Confirma se o npm disponibiliza a versão oficial e o binário: npm view breezecss-cli version bin --prefer-online. Se aparecer uma versão temporária como 0.0.0-stage, aguarda o processamento da publicação. Se já tens uma instalação local antiga, remove-a e instala breezecss-cli@1.0.0.

CMD / TERMINAL
npm view breezecss-cli version bin --prefer-online
npm uninstall breezecss-cli
npm install -D breezecss-cli@1.0.0
npx breeze --version

breeze não é reconhecido no Windows

O comando breeze está instalado localmente em node_modules/.bin, que não entra automaticamente no PATH do CMD. Executa npx breeze após a instalação local ou cria um script npm. Para executar sem instalar, usa npx breezecss-cli.

As cores do tema não aparecem

Confirma que o HTML contém BreezeCSS.init({ tema: { cores: ... } }) ou que breeze.config.js define as cores. O CLI 1.0.0 dá prioridade ao init dos HTML da raiz e exclui os próprios exemplos. Se tiveres vários temas no mesmo build, lembra-te de que o tema é global por compilação.

BASH
npx breezecss-cli --split --plugins auto --inject --verbose

BreezeCSS is not defined

Usa a versão 1.0.0 com proteção de chamadas inline e recompila com --inject. O guard utiliza typeof BreezeCSS !== 'undefined', não if (BreezeCSS). Confirma que o HTML está a carregar o js/<pagina>.runtime.js correto. Scripts JS externos não são modificados automaticamente.

Progress e Scrollbar têm a mesma cor do fundo

Verifica se progress-track[...] resolve para uma cor válida e se scrollbar-track[...] está definido. Por exemplo:

HTML
<body class="progress progress-track[#fff] progress-color[#005]
             scrollbar scrollbar-track[#003] scrollbar-thumb[#ffffff88]">

Os efeitos de Backgrounds ou Preloader não aparecem

Esses plugins dependem do runtime JavaScript. Compila com --plugins auto --inject e confirma que o ficheiro js/<pagina>.runtime.js é carregado. Evita scripts personalizados que escondam o preloader antes da animação de saída.

As classes do React não são geradas

Usa --tpl e, para classes montadas dinamicamente, --safelist. Confirma também que os ficheiros da aplicação estão dentro do projeto analisado e não foram excluídos.

O CLI está a compilar HTML de exemplos

Executa o comando na raiz do teu site e limita a seleção com --file ou --exclude. A pasta do próprio CLI é excluída automaticamente, mas outras pastas de exemplos criadas no projeto podem precisar de exclusão explícita.

16 / 16Ajuda

Respostas rápidas

Qual é o comando oficial para executar sem instalar?

npx breezecss-cli --split --plugins auto --inject. O pacote publicado chama-se breezecss-cli; o seu executável chama-se breeze. Depois de instalar localmente com npm install -D breezecss-cli, também podes usar npx breeze.

Preciso de --init index.html?

Não. Na versão 1.0.0, a configuração é detetada automaticamente. --init serve apenas para forçar uma origem específica.

Posso continuar a usar BreezeCSS.addComponent()?

Sim. O CLI descobre os componentes e gera as suas regras no CSS. A versão compilada também inclui uma API de compatibilidade quando o runtime está presente.

O --inject remove a CDN original?

Para referências reconhecidas do Breeze, sim. Substitui a primeira referência pelo runtime e trata as restantes. Não remove CDNs de bibliotecas diferentes, como Emerge ou Elyra.

--inject remove o meu JavaScript?

Não. Protege chamadas independentes ao BreezeCSS nos scripts inline e preserva o código das outras bibliotecas. Não altera ficheiros JS externos.

Posso publicar sem breeze.bundle.js?

Sim. Publica os CSS e runtimes gerados. O bundle original é necessário ao CLI durante o build, não ao navegador no modo compilado.

Posso gerar apenas CSS?

Sim. Usa --no-runtime, sobretudo quando não precisas de efeitos JS. Para Progress, Backgrounds e Preloader, normalmente vais querer o runtime.

O que acontece se compilar duas vezes?

O --inject foi concebido para ser idempotente: atualiza referências e guards sem criar cópias sucessivas.
