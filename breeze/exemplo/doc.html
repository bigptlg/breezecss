1. Instalação

O breeze não tem dependências — só Node.js 18 ou superior. Instala localmente no projecto e usa-o via npx: 

npm install --save-dev breeze
npx breeze

Também funciona sem instalação alguma, correndo directamente o bin/breeze.js dentro da pasta do pacote.

2. Início rápido

Três passos e o CSS está pronto: escreve HTML com classes do Breeze, corre o comando e liga o ficheiro gerado. 

# 1. varre todos os **/*.html do projecto
npx breeze

# 2. resultado: css/breeze.css com tudo o que foi usado
#    liga-o nas páginas:
<link rel="stylesheet" href="css/breeze.css">

# 3. reconstrói automaticamente ao guardar
npx breeze --watch --inject

3. Modos de saída

Ficheiro único (omissão)

Todas as páginas contribuem para um só css/breeze.css. Ideal para sites pequenos e para cache partilhada entre páginas.

--split (por página)

Gera css/index.css, css/settings.css, css/doc.css… cada página recebe apenas as classes de que precisa.

--file (página única)

Processa só o HTML indicado — útil em pipelines que constroem página a página. Repetível: --file a.html --file b.html.

Combinações

npx breeze --split --minify -o dist/css — saída minificada numa pasta de distribuição, pronta a publicar.

4. Todas as opções

Opção Efeito
-o, --out Pasta de saída (omissão: css/)
-n, --name Nome do CSS único (omissão: breeze)
--split Um CSS por página HTML
-f, --file Processa apenas este(s) HTML (repetível)
--include / --exclude Globs de inclusão/exclusão (repetíveis)
-p, --prefix Prefixo das classes, ex.: bz-
--minify CSS minificado numa linha só
--no-reset / --no-smooth Sem reset / sem scroll-behavior
--safelist Força classes mesmo sem uso no HTML
--plugins / --no-plugins Regista plugins (glass, dividers, progress, scrollbar, preloader, backgrounds)
--all-plugin-css CSS completo de todos os plugins, mesmo sem uso nas páginas
--tema Tema igual ao BreezeCSS.init: JSON ou secção.nome=valor (repetível)
--config Ficheiro de config (por omissão breeze.config.js)
--engine Caminho alternativo do breeze.bundle.js
--inject Insere o <link> nos HTML (idempotente)
-w, --watch Reconstrói ao guardar
--clean Apaga a pasta de saída antes de gerar
--verbose Páginas, classes desconhecidas e avisos

5. Injecção do <link>

Com --inject, o breeze insere ou actualiza o <link rel="stylesheet"> em cada HTML, com caminho relativo correcto mesmo com --split e -o personalizada. A marca <!-- breeze:css --> torna a operação idempotente: correr duas vezes não duplica nada. 

<!-- breeze:css -->
<link rel="stylesheet" href="css/doc.css">
<!-- /breeze:css -->

6. Modo watch

npx breeze --watch --inject mantém-se activo e reconstrói o CSS assim que qualquer HTML monitorizado muda — as novas classes aparecem no ficheiro gerado no instante seguinte. Combina bem com a extensão Live Server do VS Code para um fluxo utility-first sem build step manual.

7. Prefixo de classes

-p bz- gera .bz-mt[16px] em vez de .mt[16px] — evita colisões com outras frameworks no mesmo projecto. As variantes (hover:, md:, dark:) e os transform combinados são prefixados com segurança; regras de transform sem função gerada pelo motor são substituídas por versões correctas.

8. Tema e breeze.config.js

Se o teu projecto chama BreezeCSS.init no browser com tema e plugins, o CLI exporta exactamente o mesmo — de duas formas: automaticamente, procurando o init nos .js/.mjs/.cjs e nos <script> dos .html do projecto (os identificadores BreezeGlass, BreezePreloader… são convertidos para os nomes certos), ou com um ficheiro de config explícito. 

// breeze.config.js (opcional) — o mesmo objecto do BreezeCSS.init
module.exports = {
  log: false,
  plugins: 'all',
  allPluginCss: true,
  tema: {
    cores: { primaria: '#003', secundaria: '#005', tercearia: '#fff' },
  },
}

Resultado: bg[primaria] gera background: #003 e o CSS inclui :root com --breeze-primaria e companhia. Sem ficheiro de config, também dá pela linha de comandos: 

npx breeze --tema cores.primaria=#003 --tema cores.secundaria=#005
npx breeze --tema '{"cores":{"primaria":"#003"}}' --all-plugin-css

Nota: os valores do tema resolvem nas classes de valor simples — bg[primaria], text[secundaria], border-color[secundaria], p[nome] com espacamento, font-family[nome] com fontes. O shorthand border[solid_2px_secundaria] não resolve nomes do tema (limitação do motor): usa border[solid_2px] + border-color[secundaria].

Plugins em runtime: o CSS de suporte dos plugins sai com --all-plugin-css, mas as peças criadas em runtime — o fundo do custom-bg, o DOM do preloader, a barra do progress e a refracção do glass — continuam a precisar do breeze.bundle.js + init na página.

9. Componentes (addComponent)

Componentes registados no browser com BreezeCSS.addComponent("btn", […]) são descobertos automaticamente nos <script> inline dos HTML processados e nos ficheiros .js do projecto — nada é executado, a extração é textual. O CSS exportado passa a incluir .btn { … }, as variantes .btn:hover { transform: … } e as @media dos membros com breakpoints. 

<script>
  BreezeCSS.addComponent("btn", [
    "no-underline", "text[tercearia]", "p[15px]", "inline-block",
    "rounded[10px]", "hover:translate-x[3px]", "hover:translate-y[-3px]",
    "rounded-full",
  ]);
</script>

Também podem ficar no breeze.config.js com a chave componentes (alias components) — útil quando os componentes vêm de um JS externo que o CLI não vê: 

// breeze.config.js
module.exports = {
  componentes: {
    btn:  ['no-underline', 'p[15px]', 'hover:translate-x[3px]'],
    card: ['glass', 'glass-md', 'rounded[20px]', 'md:p[64px]'],
  },
}

Notas: em --split, cada página só traz os componentes que usa. Os nomes registados deixam de aparecer na lista “classes não geradas”. Com --prefix, os membros são prefixados automaticamente (p[15px] → bz-p[15px]) e o componente também responde a bz-btn. O relatório mostra “componentes exportados: …” com a origem.

10. Safelist, plugins e motor

  • --safelist p[99px],hidden — inclui classes mesmo que nenhum HTML as use (conteúdo dinâmico em JS/PHP).
  • --plugins glass,dividers — regista só estes plugins; --no-plugins desliga todos. O CSS dos plugins não usados é filtrado fora.
  • --engine ./breeze.bundle.js — resolve o motor por esta ordem: caminho dado, projecto, pastas acima, cópia incluída em vendor/.
  • --verbose — mostra as páginas processadas e qualquer classe não reconhecida, ideal para apanhar gralhas.

Pronto a experimentar? Corre npx breeze --split dentro deste exemplo e abre as páginas — o CSS já vem gerado em css/.
